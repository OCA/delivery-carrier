Delivery CTT Express Portugal

CTT Express Portugal e-pool Web Services API integration with Odoo.

This module implements the ShipmentProvider SOAP API used by CTT Expresso in Portugal. It is the Portugal counterpart of delivery_cttexpress, which targets the Iberic/Tourline API used in Spain: both are CTT services but they use different endpoints, credentials and contracts, so they cannot be interchanged.

When a delivery order is validated, the module creates the shipment, attaches the shipping label to the picking and closes the shipment to obtain the carrier manifest (CA1) document.

The API does not provide shipment cancellation, tracking or pickup scheduling operations, so those features are not implemented.

Installation

This module needs the zeep python library, already required by Odoo. It depends on the modules delivery_package_number and delivery_price_method that can be found on OCA/delivery-carrier.

The following hosts should be visible from your Odoo deployment:

  • Test: logistica.cttexpresso.pt:8082
  • Production: cttexpressows.ctt.pt

For mobile numbers to be sent to CTT in the dedicated field, the OCA partner_mobile module (OCA/partner-contact) is recommended, as Odoo 19 no longer provides res.partner.mobile natively.

Configuration

The CTT Express Portugal API doesn’t provide shipping price calculation methods. So you’ll have to rely on Odoo standard methods selecting them in the field Price method (the module defaults it to Based on Rules).

To configure your CTT Express Portugal account, go to:

  1. Inventory/Sales > Configuration > Delivery methods and create a new one.
  2. Choose CTT Express Portugal as provider.
  3. In the CTT Express Portugal page, configure your e-pool credentials: authentication ID, client ID, contract ID, distribution channel ID and user ID.
  4. Optionally configure the Test environment credentials. Empty fields fall back to the production values. The carrier Test mode/Production mode toggle (Environment field) selects which endpoint and credentials are used for shipments.
  5. Choose the Sub product (Para amanhã, Em 2 dias or 19 Múltiplo), the label format (PDF or ZPL), whether sender information is printed on the label, and the export type and UPU code.

You can check the connectivity and credentials of each configured endpoint with the Test connection button. It performs a harmless close-shipment probe because the API has no ping operation.

Usage

The shipping codes are generated when a stock picking which carrier is configured for CTT Express Portugal as a provider is validated. The shipping label is attached to the picking according to the configured label format, and the carrier manifest (CA1) is attached after the shipment is closed.

The first object code of the shipment is stored as the carrier tracking reference and can be used in the CTT tracking page linked from the picking.

Phone numbers are normalized before being sent: numbers without a country prefix get the +351 prefix, duplicated numbers are sent only once, and mobile numbers are sent in the MobilePhone field because CTT rejects them in the Phone field.

Known issues / Roadmap

Status: draft

Decisions

  • Implemented on top of zeep instead of raw XML envelopes: the WSDL is self-contained and zeep serializes the WCF DataContracts correctly, including the strict element ordering the service requires.
  • Credentials live on the delivery carrier (production and optional test sets), following delivery_cttexpress.
  • The carrier Test mode/Production mode toggle selects the endpoint and credential set. There is no silent fallback to production.
  • No tracking, cancel, pickup or manifest-report features: the ShipmentProvider API only exposes CreateShipment, CreateShipmentWithoutPrint, CompleteShipment and CloseShipment. Rejected: proxying those features through undocumented endpoints.
  • partner_mobile is not a hard dependency: the module reads mobile with a getattr fallback so it also works without it.
